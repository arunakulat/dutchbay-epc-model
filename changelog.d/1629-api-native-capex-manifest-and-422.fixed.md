Web API with native CAPEX: `/run-pipeline` now returns the `native_capex` provenance block in its manifest, alongside the schema 1.1 label it already carried. A USD-authored run has no such block, and its manifest leaves the key out, so a USD response keeps the manifest keys it had before. An override that a native-CAPEX scenario refuses, such as an `fx.start_lkr_per_usd` spot that no longer equals the conversion rate, now returns HTTP 422 with the refusal's own message instead of the generic "see the server logs" text. This holds whether the run is started from `config` or from `config_path`. The engine still receives the authored config. The API contract version moves from 2.1 to 2.2 (a minor, additive change). The bump also covers the optional debt schedule row fields `debt_period`, `operating_year` and `phase`, which #1640 added to the same response without a bump. #1629 follow-ups from the #1645 review (DOM-1645-R4-01, ASSURANCE-1645-R11).
