- **Wind grid-capability plug-in (topology-aware reactive PQ envelope + LVRT ride-through)** (`analytics/grid/capabilities/wind.py`, `analytics/grid/capabilities/__init__.py`, `finance/grid/grid_types.py`, #876 D4b) — the first per-technology grid-capability plug-in (new `analytics/grid/capabilities/` package). Keyed on the wind turbine converter topology (`turbine.converter_type` — `type3_dfig` | `type4_full_converter`, with aliases), it builds the reactive-capability **PQ envelope** whose SHAPE is topology-dependent: a **Type-4 full-converter** turbine gives a full ~RECTANGULAR box (±Q constant across the 0→rated active-power range), while a **Type-3 DFIG** processes only rotor-slip power so its ±Q headroom **NARROWS at partial load** (scales roughly linearly with P, flooring at a small zero-P converter reserve). The governing (worst-shortfall) point of the P-sweep sets the reported Mvar shortfall vs the grid-code `gridcode.pf_range` demand and the PQ-box verdict, emitted as the reused D3 `ReactiveCapabilityResult` (advisory, `method="wind_pq_envelope"`). LVRT ride-through is driven through the shared D4a ANDES core (`analytics.grid.ride_through.run_ride_through_case`), parameterised from the same redacted D0 grid-code fixture and gated behind `run_dynamics` (default off → honest NOT-RUN LVRT advisory, no `andes` import). New wind-turbine converter discriminators land in the shared leaf registry `finance.grid.grid_types` (`is_type3_dfig` / `is_type4_full_converter` / `is_known_wind_converter_type`, a distinct axis from the GFL/GFM control-mode enums — CCCDIR single source of truth). CASPER: the reactive PQ-envelope + config math is pure Python importing no grid library; the only optional-dep path is the LVRT dynamics, delegated to the D4a `_require_andes()` call-time guard, so the default (grid-free) install imports cleanly. PURE-ADVISORY: every sub-result is `bankable=False` and nothing feeds the finance engine, so committed-scenario KPIs are byte-identical (project/equity IRR, NPV, min DSCR unchanged) — NOT the utility-accepted bankable connection study (a true FRT study is an EMT run with the OEM `.dyr`/`.dll`; the reactive PQ box is a design-stage analytical screen, not a load-flow). Grid-free tests carry 100% coverage of the new module (all PQ-envelope math, config parsing, result assembly, the gate-off plug-in path); the ANDES-backed wind LVRT solve runs in the opt-in `-m grid` lane under `pip install -e '.[grid]'`.
