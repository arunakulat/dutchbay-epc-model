Every `run_v14_pipeline` result now carries a `yield_reconciliation` block (#1768). The AEP <-> capacity-factor gate (`analytics/aep_reconciliation.py`) failed loud on a mismatch but left nothing behind when it passed, so a reader of `summary.json` could not tell a reconciled run from a run with nothing to reconcile. The block records the bankable references compared with `capacity_mw x capacity_factor x 8.760`, each signed deviation, the tolerance and whether it is an audited override of the default, the frozen-P90 comparison, a status (`reconciled`, `outside_tolerance`, `not_applicable`, `not_checked`) and whether the fail-loud gate ran on this exact configuration, with where it ran (`gate_site`): the scenario load for a scenario file, the `/run-pipeline` API boundary, or the service seam behind the `/cases` routes. An inline configuration the engine receives directly, such as a Monte Carlo trial or a screening run, is marked as not gated. It carries the run manifest's `config_sha256`; the manifest's own fields and the web API's response are unchanged. The lender report adds a "Yield reconciliation" table to its audit section, with a caveat that it discloses a consistency check and is not a yield basis. The D3C result catalogue lists the key as an audit artifact. Disclosure only: the gate is unchanged and no figure moves.
