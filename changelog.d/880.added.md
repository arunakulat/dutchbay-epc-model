- **Static hybrid-POC aggregation (composite/weighted SCR + aggregate ±Q(P) envelope)** (`analytics/grid/hybrid/poc_aggregation.py`, `analytics/grid/hybrid/__init__.py`, `analytics/grid/__init__.py`, `analytics/contracts_v14.py`, #880 D5b) — the first HYBRID-plant grid screen: where the D4b/c/d per-tech plug-ins each characterise ONE resource's converter interface, this new `analytics/grid/hybrid/` package walks the RESOLVED multi-tech resource list (`grid.resources`) and sums every resource's electrical model onto ONE point-of-connection (POC) bus, producing the two metrics that only exist for the combined fleet. (a) A **composite / weighted SCR (WSCR)**: because every IBR MW behind the POC shares the same upstream fault level, the SCR each inverter effectively sees is the POC fault level ÷ the TOTAL IBR MVA behind the POC — so adding solar/BESS behind a wind POC LOWERS the effective SCR for every inverter (a per-tech SCR against a single rating is OPTIMISTIC for a hybrid). A BESS PCS additionally STIFFENS the grid (its manual `sc_contribution_pu` from D4d enters BOTH the fault-level numerator and the IBR-MVA denominator); grid-following wind/solar ride their current limit and add ≈0 to the fault level (the D4c anti-optimism rule — never credited as a synchronous machine). The composite SCR is banded (weak/marginal/strong) + GFL/GFM-recommended by the same D1 `grid_scr_band` / `grid_gfl_gfm_recommendation` helpers. (b) An **aggregate ±Q(P) reactive envelope**: the VECTOR SUM of each resource's ±Q headroom (taken from its D4b/c/d plug-in — a Type-3 DFIG's partial-load-narrowed value, a solar inverter's pf-capability value, a BESS's SoH-degraded value) MINUS the reactive absorbed by the collector network + POC transformer (`grid.collector_transformer_q_loss_mvar` absolute or `_fraction`), screened against the grid-code reactive demand at the POC → a plant-level Mvar shortfall (the STATCOM/MSC sizing figure) + PQ-box verdict — never a single-tech box. Two frozen advisory result types are added to `analytics.contracts_v14` (CCCDIR — all grid result types centralised there): `PocCapabilityEnvelope` (the plant-level bundle) and its per-resource line item `ResourceReactiveContribution` (the vector-sum audit trail). PURE STATIC screening — NO ANDES/EMT — and it REUSES the per-tech plug-ins rather than re-deriving converter models. CASPER: no grid library is imported at module scope (the reused plug-ins guard `pandapower`/`andes` at call-time; the SCR fold uses the closed-form path in the default install). CESSPIT / NO-SPURIOUS-PASS: every required input (POC voltage, source fault level, grid-code pf_range, resource rating/tech) is strict — a missing/ill-formed value RAISES rather than defaulting into a spurious PASS. Default-off / advisory-only (`bankable=False`): nothing here feeds the finance engine, so committed-scenario KPIs are byte-identical (project IRR 0.014551597740253388 / equity IRR −0.05841298678542661 / NPV −79.27M / min DSCR 1.285740985294611 unchanged). Grid-free tests carry 100% coverage of the new module (per-resource wind/solar/BESS dispatch, the composite-SCR fold + the load-bearing "adding IBR lowers the SCR" property, the reactive vector sum net of the collector/transformer path in all three loss forms, the PQ-box verdict, and every CESSPIT strict-input raise); the aggregation has NO pandapower/andes-only lines of its own (its optional-dep paths live inside the already-grid-tested D1 SCR screen).
