- **Grid study contracts + `evaluate_grid` gateway (CCCDIR) + steady-state reactive/voltage screen** (`analytics/grid/reactive_screen.py`, `analytics/grid/evaluate_grid.py`, `analytics/contracts_v14.py`, #874 D3) — adds the reactive-capability half of the design-stage grid study on top of the D1 SCR screen (#872) and the D2 config data model (#873). Three new frozen advisory contracts join `analytics.contracts_v14` (CCCDIR — result types centralized): `ReactiveCapabilityResult` (per-resource + POC Q(P,V) capability → `mvar_required` / `mvar_available` / `mvar_shortfall` — the STATCOM/MSC sizing figure — plus `pf_at_poc` and the `inside_pq_box` verdict), `PowerFlowResult` (bus voltages pu, POC pf/voltage, `converged`) and the wrapping `GridStudyResult` that bundles `GridStrengthResult` + `ReactiveCapabilityResult` + `PowerFlowResult` under one POC. Each is `bankable=False` with provenance — never the utility-accepted PSS/E / PowerFactory study. New `analytics/grid/evaluate_grid.py` is the single CCCDIR gateway (mirroring `analytics.evaluation_v14.evaluate_with_overrides`): analytics consumers reach the grid engine ONLY here and import grid result types ONLY from `analytics.contracts_v14`; it imports neither `finance.*` nor any `analytics.pipeline_*` module. It strictly gates on `grid.study_enabled` (CESSPIT — no silent no-op) and composes the SCR screen + reactive screen into a `GridStudyResult`. New `analytics/grid/reactive_screen.py` builds an `ext_grid → POC transformer → collector bus → resources` network in **pandapower** and runs an AC load-flow (`runpp`) over a P(0→rated) × grid-voltage(code window) sweep, commanding each resource to the reactive limit from its capability curve, reading the achieved POC pf/voltage, and sizing any Mvar shortfall against the grid-code PQ box at the governing (worst) operating point; a non-converged corner is escalated as a binding failure rather than passing silently. `pandapower` is guarded at call-time via `_require_pandapower()` (CASPER) — never imported at module scope, so the default (grid-free) install imports the module cleanly. The study is DEFAULT-OFF and ADVISORY — it never feeds the finance engine, so committed-scenario KPIs are byte-identical (project/equity IRR, NPV, min DSCR unchanged). The pandapower `runpp` reactive screen + the `evaluate_grid` bundle run in the opt-in `-m grid` lane with the `[grid]` extra installed; the default suite proves the CASPER import guard and the CCCDIR import boundary statically.
