- Redis/arq durable-job cutover, explicitly gated (#663). `POST /jobs` now honours a `DUTCHBAY_JOBS_BACKEND` selector: `memory` (the default) keeps the in-process `BackgroundTasks` + `InMemoryJobStore` path — byte-identical to pre-#663 — while `redis` produces the job onto the arq queue the worker consumes (`run_wind_assessment_task` on the shared queue, passing only serializable `job_id` + payload) and resolves `get_store()` to a shared `RedisJobStore`, so the API reports the status the worker writes. Redis is an EXPLICIT opt-in (the URL has a localhost default, so it never gates the cutover on its own) requiring the optional `[jobs]` extra + a live Redis; when the backend is `redis` but the extra is absent, resolution fails loud (CASPER) with an actionable install hint rather than degrading silently. Queue name + Redis DSN are single-sourced in `app/jobs/config.py` (CCCDIR — the API enqueue path and the worker agree). The Redis round-trip cannot be CI-verified without a live broker, so the default stays `memory`; the gate, the memory-path byte-identity, and the fail-loud guard are unit-tested. Lands the #788 Phase-1 durable-job path.
