The solar + BESS sizing summary no longer stamps or pins `VERSION`. A run records
`spec.inputs_digest`, one SHA-256 over the code tree, the config and scenario files it
read and the sizing config. The committed-summary check now fails when a unit, pricing,
scenario or regulatory file it recorded changes, or when the sizing config's values
change, rather than when `VERSION` moves; it does not compare the code digests. A version bump therefore no longer
forces the ~70-minute regeneration (#1864; `RELEASING.md` notes). No figure, config, scenario or
committed summary changes.
