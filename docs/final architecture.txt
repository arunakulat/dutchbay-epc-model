## 2️⃣ What ARCHITECTURE_LAYERS adds (and nails down)

This doc basically locks the contracts story into a clean 4-layer stack:

1. **Layer 1 – Import interface**

   * Old: `from analytics.contracts_v14 import ShockSpec`
   * New: `from analytics.contracts import ShockSpec`
   * Internal (rare): `from analytics.contracts._phase_3_sensitivity import ShockSpec`
   * All three are supported; new one is preferred.

2. **Layer 2 – Legacy wrapper (`analytics/contracts_v14.py`)**

   * ~80 lines, **pure re-exports** from the modular package.
   * Guarantees:

     * No code duplication
     * Backward compatibility “forever”
     * Zero behavioural change on old imports.

3. **Layer 3 – Modular facade (`analytics/contracts/__init__.py`)**

   * ~150 lines of imports from 8 phase modules + `__all__`.
   * Single, modern entry-point for all contracts.

4. **Layer 4 – Implementation modules (8 of them)**

   * `_phase_1_base.py` – WACC / lender / debt + `DebtCovenantSnapshot` + `_build_debt_covenant_snapshot`.
   * `_phase_1_cashflow.py` – `CashflowResult`, `ScenarioResult`, `build_cashflow_result_from_annual_rows`.
   * `_phase_1_equity.py` – `EquityPerformance`, `DownsideMetrics`.
   * `_phase_2_tail_risk.py` – `Distribution`, `DerivedParameter`, `MonteCarloScenario`, `MonteCarloResult`, tail-risk metrics.
   * `_phase_3_sensitivity.py` – **CRITICAL**: `ShockSpec`, `ShockResult`, `SensitivitySuite`, `StandardShockLibrary`, `ParameterRangeConfig` (deprecated).
   * `_phase_3_advanced.py` – `BreakevenResult`, `MultiMetricTornadoResult`, `MultiMetricSensitivitySuite`, `ParetoFrontierResult`.
   * `_phase_4_casper.py` – CASPER payload: `GenerationProfile`, `TechnologyBreakdown`, `MultiTechGenerationResult`, `CasperResult`, `build_casper_payload`.
   * `_helpers.py` – `ScenarioDescriptor`, validators, factories.

Plus:

* A **governance matrix** explicitly mapping CCCDIR / CESSPIT / CASPER / GWTF / No-Regression to concrete implementation locations (frozen contracts, `__post_init__` validation, ShockResult metrics, gateway usage, wrapper).
* A **migration strategy** (gradual, big-bang, hybrid) with your recommended path = gradual / hybrid.

Short version: this doc is the “single source of truth” for how contracts v14 is *meant* to sit in the repo.
